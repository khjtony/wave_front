A finite concurrent-game framework with three interchangeable engines, an evidence pipeline that turns dated documents into start states, and a claim protocol that fixes every expected result before a guard is written. Drawn from the code at the current head of the development branch.

Reading the diagrams

One question, three engines. Every forcing or kernel question is a coalition, a target and a horizon. The explicit engine builds the graph and runs fixpoints on it; the bounded checker unrolls k steps into Z3 and explains failures with unsat cores; the symbolic engine runs the same fixpoints on BDD-encoded state sets, with a compiled core when the sets are large. Results are cross-checked across engines in the test suite.

Snapshots carry more than levels. A start state includes the built-ins the model needs to be consistent at that tick: pending delayed decisions, last moves, latched history and fairness counters, computed along the realized path.

The protocol is part of the system. Claims are registered before guards, a first-sight commit is recorded, failures are reported as computed, and amendments are the owner's decisions written as dated changelog rows. The diagrams draw those steps because the results mean nothing without them.
